# ContextTrace-Unseen-v1 adjudication protocol

Protocol version: 1.0

Status: protocol only; no disagreements exist

## Preconditions

Adjudication may begin only after:

- independent raw submissions are complete and immutable;
- each submission has a recorded SHA-256;
- schema and offset checks pass;
- agreement metrics are computed from raw, pre-adjudication values;
- the adjudicator confirms no access to system predictions;
- the disagreement packet is generated by deterministic comparison.

Do not correct raw annotations before agreement analysis.

## Disagreement packet

For each disagreement, show:

- blinded case and claim identifiers;
- query, answer, approved sources, retrieval stages, and citations;
- both raw annotator values with pseudonymous IDs;
- relevant manual section;
- evidence spans and rationales;
- no ContextTrace or baseline output.

Claim-boundary disagreements include both proposed spans and the answer text.
Evidence-span disagreements include exact source offsets and text.

## Adjudication unit

Record one immutable event for each:

- claim-boundary addition, deletion, split, merge, or offset disagreement;
- categorical-field disagreement;
- primary/secondary-cause disagreement;
- evidence-span source, role, boundary, or omission disagreement;
- source-condition evidence disagreement;
- correction of a schema-valid but demonstrably clerical error.

Each event records:

- event ID;
- case and claim IDs;
- field;
- every annotator value;
- selected value;
- disagreement type;
- evidence considered;
- rationale tied to the guide;
- adjudicator pseudonym and timestamp;
- raw-submission hashes.

Allowed disagreement types:

- `boundary`;
- `definitional`;
- `evidentiary`;
- `scope_or_applicability`;
- `clerical`;
- `source_metadata_defect`;
- `unresolved`.

## Decision procedure

1. Verify the disagreement is real and not an ID/alignment error.
2. Re-read the relevant trace and source material.
3. Apply the frozen guide without considering system behavior.
4. Prefer the narrowest claim boundary preserving material meaning.
5. Require direct evidence for fine-grained pipeline causes.
6. Use `not_observable` or `unknown` when the trace cannot resolve the field.
7. Record the selected value and rationale.
8. If source metadata is defective, stop that case and record
   `source_metadata_defect`; do not guess.
9. If the guide genuinely does not determine a value, record `unresolved` and
   follow the amendment rule.

The adjudicator may select one annotator value or a third value justified by the
guide. A third value is not evidence that either raw annotation should be
overwritten.

## Claim-boundary changes

When a boundary changes, assign stable adjudicated claim IDs and record lineage
to every raw claim ID. Re-evaluate all dependent fields for the new adjudicated
claim. Do not mechanically copy a label from a larger or smaller raw claim.

Agreement metrics remain based on the original boundaries.

## Guide defects

If pilot adjudication exposes a guide defect, revise the guide before the test
guide freeze and reannotate affected pilot cases.

After untouched annotation begins:

- a wording clarification with no semantic effect is logged;
- a semantic rule change creates a new guide version;
- affected test annotations are quarantined;
- an independent integrity review decides whether blind reannotation remains
  possible;
- no change is made after system results are visible.

## Gold construction

After every required disagreement is resolved:

1. construct adjudicated records from the event ledger;
2. validate against `ANNOTATION_SCHEMA.json`;
3. verify claim and evidence offsets against source bytes;
4. ensure every gold value has raw lineage;
5. preserve unresolved fields explicitly;
6. sort deterministically by case, claim offset, and claim ID;
7. hash raw submissions, ledger, and adjudicated gold separately;
8. seal them under the label custodian.

The gold file cannot be copied into the implementation workspace.

## Corrections

Post-seal corrections are append-only:

- preserve the original artifact and hash;
- create a correction event with reason and discoverer role;
- state whether predictions or results were visible;
- create a new gold version and hash;
- determine whether confirmatory evaluation remains valid.

Never silently edit or replace a sealed file.

## Reporting

Report:

- disagreement count per field;
- disagreement type per field;
- adjudicator third-value rate;
- unresolved count;
- claim split/merge count;
- source-metadata defects;
- raw-to-gold change rate;
- no adjudicated values inside pre-adjudication agreement statistics.

No combined agreement statistic is permitted.
