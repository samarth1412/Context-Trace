# ContextTrace v1.3.0

Release date: 2026-10-01. Built and published from the exact commit that passed
the repository CI and release workflow.

ContextTrace v1.3.0 adds local evidence-integrity diagnostics for a failure that
claim scoring alone cannot explain: a RAG transformation kept a fragment while
dropping a linked answer, qualifier, condition, or value captured with its source.
The stable `semantic_v1_calibrated` verifier remains the default and its verdict
behavior is unchanged.

## Highlights

- Captures explicit source-to-selection lineage with `build_evidence_lineage`.
- Reports `linked_part_dropped`, `material_span_dropped`, and
  `selected_text_not_in_source` as observed findings.
- Keeps missing and malformed lineage unknown instead of inferring a cause.
- Adds `contexttrace inspect --fail-on evidence_integrity` and
  `--fail-on unknown_integrity` for repeatable CI gates.
- Carries observed integrity failures into evidence-backed repair plans.
- Adds dependency-optional bindings for real LangChain `Document` and
  LlamaIndex `TextNode`/`NodeWithScore` objects. The helpers clone selected
  objects and preserve IDs, scores, metadata, and callback capture paths.
- Preserves local-first operation: the feature makes zero model and network
  calls and does not require Jev or another hosted judge.

## Acceptance evidence

The SHA-256-locked acceptance benchmark separates eight development cases from
ten held-out cases. The held-out set covers generic, LangChain, and LlamaIndex
trace shapes, all three observed issue types, complete captures, invalid
lineage, mixed captured/uncaptured contexts, normalization, and repeated
material-span loss.

- Exact outcomes: 10/10.
- Dangerous false greens: 0.
- Unknown handling: 2/2 exact.
- Per-issue precision, recall, and F1: 1.0 on this contract set.
- Model calls: 0.
- Network calls: 0.

These fictional cases validate the deterministic API contract. They do not
measure natural-traffic prevalence, semantic importance of undeclared text, or
state-of-the-art claim-verification quality.

## Jev boundary

Jev remains an isolated research comparator. Earlier frozen experiments show
that it can improve semantic judgment on selected evidence, while also showing
false-support and calibration risk. Version 1.3.0 does not add a production Jev
provider, send trace data remotely, or change `local_only` behavior.

## Install and use

```bash
python -m pip install contexttrace==1.3.0
```

```python
from contexttrace import build_evidence_lineage, capture_rag_trace

source = "Question: When? Answer: After approval."
lineage = build_evidence_lineage(
    source_unit_id="refund_qa",
    source_text=source,
    linked_parts=[
        {"id": "question", "role": "question", "text": "Question: When?"},
        {"id": "answer", "role": "answer", "text": "Answer: After approval."},
    ],
)
trace = capture_rag_trace(
    query="When?",
    answer="After approval.",
    contexts=[{"id": "selected", "text": "Question: When?", "metadata": lineage}],
)
```

```bash
contexttrace inspect trace.json --fail-on evidence_integrity
contexttrace repair trace.json --out repair.md
```
